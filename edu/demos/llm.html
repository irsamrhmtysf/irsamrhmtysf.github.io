How Large Language Models Work

Interactive explorations of tokenisation, next-token prediction, temperature sampling, and hallucination — the core mechanisms behind GPT, Claude, and Gemini.

What is a Token?

LLMs don't read characters or words — they read tokens. A token is roughly 3–4 characters. The model's vocabulary is typically 50,000–100,000 tokens.

Key tokenisation facts
• 1 token ≈ 4 characters or ¾ of an English word
• 100 tokens ≈ 75 words (1 paragraph)
• GPT-4 context: 128,000 tokens (~96,000 words)
• Rare words are split into multiple tokens
• Code is denser: 1 token ≈ 2.6 chars

Next-Token Prediction

LLMs are trained on a simple task: given all previous tokens, predict the next one. This is called autoregressive language modelling. Everything — reasoning, coding, conversation — emerges from this one objective.

Training objective: Cross-Entropy Loss

At each position, the model predicts a probability over all ~50,000 tokens. Loss = how surprised the model was by the actual next token.

// Simplified autoregressive training for each token t in sequence: logits = transformer(tokens[0..t-1]) // predict loss = cross_entropy(logits, tokens[t]) // compare backprop(loss) // learn // Trained on trillions of tokens → general intelligence emerges

Temperature & Sampling

Temperature controls how "creative" the model is. Low temperature → deterministic (most likely token). High temperature → random, creative, surprising.

Sampling methods
Greedy: Always pick the highest-probability token. Deterministic but repetitive.
Top-K: Sample from the K most likely tokens only. GPT-4 uses top-k=50 by default.
Top-P (nucleus): Sample from the smallest set of tokens whose cumulative prob ≥ P. More adaptive.

Why LLMs Hallucinate

Hallucination is when an LLM confidently generates false information. It's not a bug — it's a fundamental property of how these models work. Understanding it is critical for safe deployment.

Why it happens

• The model predicts plausible continuations, not true ones
• No internal "fact-checker" — just pattern completion
• Training data has contradictions, outdated info, and errors
• The model can't distinguish memory from inference
• RLHF trains for confident-sounding responses

How to mitigate

• RAG: Retrieval-Augmented Generation adds real sources
• Ask the model to cite sources and check them
• Lower temperature for factual tasks
• Never use LLMs for medical/legal decisions without verification
• Fine-tune on domain-specific verified data
