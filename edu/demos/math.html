🤔 "Why do I need math for AI? Can't I just use libraries?"

Vectors — how AI describes anything

A vector is just a list of numbers. That's it. But this simple idea lets AI describe everything — a photo, a sentence, a customer, a product — as a point in space. Then AI finds similar things by measuring distance.

Real AI example: When Spotify recommends a song, it converts every song into a vector of ~200 numbers (tempo, danceability, energy, loudness…). Your taste is also a vector. Recommendation = find vectors closest to yours.
Every streaming service, every "you might like…" feature, every search engine uses this exact idea.
// A house described as a vector house = [size_m², bedrooms, age_years, price_M] house = [120, 3, 10, 0.45]
// AI finds similar houses by distance distance = √((120-115)² + (3-3)² + ...)
Key insight: Once you convert anything to a vector, you can measure similarity. "Similar movies," "similar customers," "similar medical cases" — all find similar vectors.

Where do vectors appear in AI?
🗣 Word2Vec: "king" → [0.3, -0.7, 0.9, …] (300 numbers). Similar words → similar vectors. king − man + woman ≈ queen. This is real.
👤 Face recognition: Your face → 128 numbers. Login matches if distance to stored vector < threshold.
🛒 Recommendations: You + product both become vectors. Dot product = predicted rating.
Vector operations in AI
a = [2, 3] b = [1, 4]
// Dot product (similarity) a·b = 2×1 + 3×4 = 14
// Magnitude (length) |a| = √(2²+3²) = 3.61
// Cosine similarity (AI standard) cos_sim = (a·b)/(|a|×|b|) = 0.97
High-dimensional space

GPT-4 represents every token as a vector with 12,288 dimensions. You can't visualise that. But the math works identically — dot products, distances, similarity — just with 12,288 numbers instead of 2.

Matrices — the engine of neural networks

A matrix is a table of numbers. When a neural network processes your photo, it multiplies the pixel values by millions of weight matrices. Every forward pass, every prediction — it's all matrix multiplication.

Real AI example: A neural network layer with 1000 inputs and 1000 outputs performs one matrix multiplication: (1000×1000) × (1000×1) = (1000×1). That's 1 million multiplications in one step. GPT-4 does billions of these per token it generates.

Gradient Descent — how AI learns

Gradient descent is the one algorithm that trains almost every AI model you've ever used. It finds the bottom of a bowl — the configuration of weights that makes the model as accurate as possible — by always moving in the downhill direction.

Real AI example: Training GPT-4 ran gradient descent for months, adjusting 1.8 trillion numbers (weights) simultaneously, billions of times. The "loss" it minimised: how surprised was the model by the next word in the training text? After enough steps, the model got very good at predicting text — and surprisingly good at everything else.

The algorithm, step by step
1
Calculate loss
Measure how wrong the model is right now. Loss = average error across all training examples. High loss = very wrong.
2
Calculate the gradient
For every weight: "if I increase this weight by a tiny bit, does loss go up or down?" This is calculus — the partial derivative. Modern AI auto-computes this with backpropagation.
3
Update weights
Move every weight a small step in the direction that reduces loss. weight = weight - learning_rate × gradient. Learning rate controls step size.
4
Repeat billions of times
Eventually the model reaches a minimum — it can't improve further. GPT-4 took months. Your neural net demo takes seconds.
Learning rate: the most important hyperparameter
Learning rateEffect
Too high (1.5)Overshoots! Bounces around, never settles
Too low (0.001)Crawls. Takes forever to converge
Just right (0.1–0.3)Smooth descent to the minimum ✓

Try the slider above at 1.5 on "hills" to see divergence — the ball flies off the chart. This happens in real training when LR is misconfigured.

// Gradient descent update rule — used in every major AI θ = θ - α × ∇L(θ) // θ (theta) = model weights (what we're updating) // α (alpha) = learning rate (how big each step is) // ∇L (nabla L) = gradient of loss (the "slope" at current position) // In code (PyTorch): optimizer.step() does this automatically

Probability — AI's language of uncertainty

AI never says "this is a cat." It says "this is a cat with 94.3% probability." Understanding probability is understanding what AI is actually saying — and when not to trust it.

Real AI example: When ChatGPT generates text, it doesn't pick the "correct" next word. It computes a probability distribution over its entire 50,000-word vocabulary, then samples from it. "The Eiffel Tower is in Paris" — Paris gets 96% probability. Berlin gets 1%. Randomly selecting from these probabilities is why ChatGPT sometimes says something unusual — and why it's creative.

Statistics — reading data honestly

Before any AI trains, someone has to understand the data. Statistics is how we summarise, sanity-check, and find patterns in raw numbers. Bad statistics = bad AI, guaranteed.

Real AI example: In 2018, Amazon scrapped an AI hiring tool after noticing it discriminated against women. Why? Statistical analysis revealed the training data (10 years of Amazon's mostly-male hires) had biased patterns that the model learned. Statistics caught what pure model accuracy hid.

The 5 statistics every AI practitioner needs
// 1. Mean — the average μ = Σxᵢ / n ← sum all, divide by count
// 2. Variance — spread of data σ² = Σ(xᵢ - μ)² / n
// 3. Std Dev — interpretable spread σ = √(variance)
// 4. Correlation — how two things relate r = Σ(xᵢ-μₓ)(yᵢ-μᵧ) / (n·σₓ·σᵧ)
// 5. Z-score — how unusual is a value? z = (x - μ) / σ ← used in normalisation
Why std dev matters for AI training

Neural networks train much faster when input features are normalised — typically rescaled to mean=0, std=1. Without this, some features dominate others just because of their scale (e.g. "age" vs "salary").

// Feature normalisation (StandardScaler) x_norm = (x - mean) / std_dev // Now every feature: mean≈0, std≈1
🤖 Used in: Spam filters · Medical diagnosis AI · Naive Bayes classifiers · Probabilistic reasoning

Bayes' Theorem — updating beliefs with evidence

Bayes' theorem is the mathematically correct way to update a belief when you get new evidence. It's how a spam filter learns, how medical AI diagnoses, and how AI handles uncertainty. The formula looks scary. The idea is obvious.

The intuition in one sentence: Prior belief + new evidence = updated belief. A medical test that is 99% accurate is NOT 99% reliable — it depends on how rare the disease is. Bayes' theorem is the only way to get the right answer.

The formula — and what each part means
P(disease | positive test) = P(positive | disease) × P(disease) ───────────────────────────────── P(positive)
// P(disease) = prior (how common is it?) // P(positive|disease) = test sensitivity // P(positive) = all ways to test positive
// Expand denominator: P(positive) = P(pos|disease)×P(disease) + P(pos|healthy)×P(healthy)
The shocking result: A 95% accurate test for a disease affecting 1% of people → only ~16% of positive tests are real. 84% are false alarms. This is why doctors don't rely on one test alone. Bayes explains why.
Where AI uses Bayes every day
📧 Spam filter: P(spam | "free offer") updates every time you mark an email. Learns your personal definition of spam.
🩺 Medical AI: Starts with disease prevalence, updates on symptoms, test results, age, history.
🔍 Search ranking: P(relevant | query) combines prior belief about the page with evidence from your query.
🚗 Self-driving: Constantly updating P(pedestrian | sensor data) as new sensor readings arrive.
